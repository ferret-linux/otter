# Using Otter as Your Default CLI/Shell

Otter has no switch that makes *every* terminal session enter a
container — that's deliberate, and it's a shell/terminal concern,
not an otter one. What otter does give you is a stable way to
detect "am I inside a container?" and a frictionless `enter`. This
tutorial shows how to wire that into a default.

Otter sets the `CONTAINER_ID` environment variable to the box name
inside every container. If the variable is **absent**, you're on
the host; if it's **set**, you're already inside a box. All the
recipes below gate on that.

## Recipe 1: auto-enter via your shell RC (host → box shell)

Append to your host RC (`.bashrc`, `.zshrc`, `.config/fish/
config.fish`, nushell `login.nu`, ...):

```sh
# ~/.bashrc (host)
if [ -z "$CONTAINER_ID" ] && [ -n "$PS1" ]; then
  exec otter enter mybox
fi
```

- `exec` replaces the shell, so the box shell *is* your terminal.
- The `$CONTAINER_ID` guard is essential: without it, the box's RC
  would read the same rule and re-enter forever. In the container
  the var is set, so the rule no-ops.

## Recipe 2: a per-shell trigger (only custom shells)

If you want the host shell choice to survive (deeper history, your
host prompt) and only *fall back* to the container for a specific
shell, trigger on the shell you enter with:

```sh
otter enter mybox -- zsh
```

And in your box RC, keep the same container so tools you use stay
installed in one place.

## Recipe 3: terminal profile = "container it is"

Many terminals (Alacritty, kitty, foot, ghostty, Konsole) let a
profile be an arbitrary command. Point one at:

```sh
otter enter mybox
```

New *windows* open in the box directly, while your normal profile
stays host-side — the same dialog applies when picking a box:
you get a dev terminal and a normal terminal side by side, sharing
the same home directory.

## Escape hatches

- **Back to the host in the same terminal**: type `exit` (leaves
  the container), then `exit` again (closes the host shell) —
  `CONTAINER_ID` goes unset the moment the box shell ends.
- **A one-off on the host**: `otter host-exec <cmd>` (see
  `otter host-exec`) or a second terminal/tab.

## Caveats

- The auto-enter recipe starts your *entire* session inside the
  box. Exporting apps and binaries (`otter export`) still matters for
  GUIs and launchers, which don't read your RC.
- `--no-tty` scripts never trigger the guard (`PS1` is empty in
  non-interactive use), so cron/`ssh` stay on the host unless you
  say so.
- Pick the box that will actually be your default *before* wiring
  a rule — changing later is just editing one line in `$RC`.
