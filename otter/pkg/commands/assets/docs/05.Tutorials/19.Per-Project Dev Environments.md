# Per-Project Dev Environments

A common otter pattern is one container per project: each box
carries exactly the toolchain, services, and versions that project
needs, and switching projects means switching containers. Because
your home directory is shared into every container, your code and
configs are visible everywhere — what differs is the environment.

## Create a project box

```sh
otter create --image ubuntu --additional-packages "git nodejs yarn" my-api
```

- `--additional-packages` installs the toolchain at first boot.
- `--init` gives the box a real service manager if the project
  needs a database or dev server supervised (see Initful vs
  Initless).

Environment variables aren't a create-time concept: begin each
session with `--add-env "NAME=value"` (or just `--add-env NAME`
to copy one from the host). `--empty-env` and `--clean-path` give
a controlled, host-free environment when you need it:

```sh
otter enter my-api --add-env "NODE_ENV=development"
```

## Working directory mapping

`otter enter` maps your current host directory into the container
automatically:

- If your cwd is inside your home, it's translated to the same path
  in the container (home is mounted identically).
- If it's outside your home, it appears at `/run/host/<path>`.

So from a project folder under your home you can just:

```sh
otter enter my-api -- npm test
```

and it runs in the right directory. `--no-workdir` always starts
from the container's home instead, and a custom entry is possible
via the mapping above. See `otter enter`.

## Sites outside the home

For a project living somewhere like `/srv` or an external drive,
either work through `/run/host`, or bind it into a nice path at
create time:

```sh
otter create --image arch \
  --additional-flags "-v /srv/my-project:/project" \
  proj-box

otter enter proj-box -- cd /project '&&' make
```

(Add the `,Z`/`:Z` suffix to the volume if SELinux relabeling is
needed on your host.)

## Declare the whole environment in a manifest

For reproducibility — new machine, or the whole team — declare the
project box in TOML:

```toml
[[container]]
name  = "my-api"
image = "ubuntu"

[settings]
init-system = true

[additional]
packages = ["git", "nodejs", "yarn", "postgresql"]
volumes  = ["/srv/my-project:/project"]
```

```sh
otter assemble create --file project.toml
```

Now every developer's box is identical. See
`Declarative Manifests & Assemble`.

## IDE & editor integration

With your home shared, editor config and caches inside the
container and on the host are the same files, and otter's VS Code
bridge wires editors into the boxes. See `IDE Integration` and
`Host Integration`.

## Tips

- Keep one container per project, not one giant container for
  everything — recreating and upgrading a single-purpose box is
  cheap, and manifests keep them all defined.
- Bake the toolchain into a custom image to skip per-box first-boot
  setup — see `Custom Image Build Cookbook`.
- Snapshot a project box before big changes with `otter create
  --clone` — see `Backing Up, Cloning & Restoring`.
