# USB & Devices

Otter containers share the host's `/dev` by default, so most
hardware just works: USB storage appears under `/run/media`, a
webcam shows up as a device node, and kernel driver devices are
visible. This tutorial covers the cases that need a bit more.

## Default behavior

- `/dev` and `/sys` are bind-mounted into the container unless the
  container was created with `--unshare-devsys`.
- In a rootless container your device access is still gated by your
  host user's permissions — a device *you* can't read from the host
  shell isn't magically readable in the container.

So the rule of thumb is: if your host user can `ls`/open the node,
the container can too. Hardware like game controllers, webcams, and
thumb drives typically needs *nothing* extra.

## Passing extra device rules with `--additional-flags`

When a device needs an explicit node or rule (hotplugged nodes that
appear mid-run, or a device the container should get regardless of
user permissions), use `--additional-flags` at create time to hand
the container manager a `--device` line:

```sh
otter create --image debian --additional-flags \
  "--device /dev/bus/usb:/dev/bus/usb" arduino-box
```

A whole class of input devices, for drawing tablets and
controllers, goes through the `uinput` driver. If the host has
`/dev/uinput` available, make sure it's present inside:

```sh
otter create --image arch \
  --additional-flags "--device /dev/uinput:/dev/uinput" \
  drawing-box
```

The kernel `uinput` module must be loaded on the host (`lsmod |
grep uinput`); the container can't load kernel modules itself.

## Permissions gotchas

- **Group membership** — if the host needs you in `input`, `video`,
  or `uinput` groups, joining that group on the host is what grants
  the container access. Note `--unshare-groups` containers don't
  forward host group membership at all; recreate without it (or use
  a rootful container) if group-based device access matters.
- **Rootless containers** — some device operations (mounting,
  ioctls to certain subsystems) still touch things a rootless
  user-namespace blocks. For device-heavy or kernel-adjacent work,
  a rootful container may be required. See `Rootful vs Rootless`.
- **`--unshare-devsys`** — this flag removes *all* `/dev` sharing,
  including `/dev/kvm` passthrough. If a VM stack inside the
  container needs that device, don't combine it with unsharing
  devices. See `Using KVM & Libvirt in Containers`.

## Checking what the container sees

Inside the container, compare the node with the host:

```sh
otter enter my-box -- ls -l /dev/bus/usb /dev/uinput 2>/dev/null
```

If the node is missing, recreate with the appropriate
`--additional-flags` device line — mounting a device node is a
create-time decision, not something `enter` can add later.
