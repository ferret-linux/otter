# Running Behind a Corporate Proxy

If your network requires a proxy, configure it before the container's
first initialization, because Otter may need network access while it
installs packages. Host proxy variables are not consistently passed
through every container manager, so pass them explicitly as container
environment variables. For APT, an `apt.conf.d` setting is another
reliable option.

## Why apt needs special handling

APT supports the lowercase `http_proxy` environment variable and also
provides explicit proxy settings through `/etc/apt/apt.conf.d/`.
Explicit configuration is useful when the container manager does not
forward the host environment or when you need separate HTTP and HTTPS
proxy settings.

## Debian / Ubuntu

Use `--additional-flags` to pass proxy variables into the container,
and `--pre-init-hooks` to write APT's proxy config before package
installation:

```sh
PROXY=http://proxy.example.com:3128

otter create \
  --image debian \
  --additional-flags "--env http_proxy=${PROXY} --env https_proxy=${PROXY}" \
  --pre-init-hooks "echo 'Acquire::http::Proxy \"${PROXY}\";' > /etc/apt/apt.conf.d/proxy.conf && echo 'Acquire::https::Proxy \"${PROXY}\";' >> /etc/apt/apt.conf.d/proxy.conf" \
  deb
```

The pre-init hook writes the APT settings before package installation.
The `--env` flags make both variables available during initialization
and in later programs inside the container.

To make the variables available in interactive sessions, add them to
the container's shell profile as well:

```sh
PROXY=http://proxy.example.com:3128

otter create \
  --image debian \
  --additional-flags "--env http_proxy=${PROXY} --env https_proxy=${PROXY}" \
  --pre-init-hooks "echo 'Acquire::http::Proxy \"${PROXY}\";' > /etc/apt/apt.conf.d/proxy.conf && echo 'Acquire::https::Proxy \"${PROXY}\";' >> /etc/apt/apt.conf.d/proxy.conf && echo 'export http_proxy=\"${PROXY}\" https_proxy=\"${PROXY}\"' >> /etc/profile.d/proxy.sh" \
  deb
```

## Fedora / RHEL / CentOS

`dnf` can use the proxy environment variables. Pass them explicitly so
they are available during initialization:

```sh
PROXY=http://proxy.example.com:3128

otter create \
  --image fedora \
  --additional-flags "--env http_proxy=${PROXY} --env https_proxy=${PROXY}" \
  fed
```

To persist the variables for interactive sessions, use a
`--pre-init-hooks` command that writes them to `/etc/profile.d/`.

## Arch / Manjaro

`pacman` can use proxy environment variables. Pass them explicitly so
they are available during initialization:

```sh
PROXY=http://proxy.example.com:3128

otter create \
  --image arch \
  --additional-flags "--env http_proxy=${PROXY} --env https_proxy=${PROXY}" \
  arch
```

To persist the variables for interactive sessions, use a
`--pre-init-hooks` command that writes them to `/etc/profile.d/`.

If your proxy requires authentication, pacman's built-in support
isn't enough — set `XferCommand` in `/etc/pacman.conf` to delegate
downloading to a tool with fuller proxy support. For example, with
`curl` installed:

```sh
PROXY=http://user:pass@proxy.example.com:3128

otter create \
  --image arch \
  --additional-flags "--env http_proxy=${PROXY} --env https_proxy=${PROXY}" \
  --pre-init-hooks "echo 'XferCommand = /usr/bin/curl -o %o %u --proxy ${PROXY}' >> /etc/pacman.conf" \
  arch
```

## Verifying it works

Enter the container and test connectivity:

```sh
otter enter deb
curl -I https://example.com
```

Any HTTP response confirms that `curl` reached a server; a `407`
response usually means proxy authentication is required or incorrect.
A timeout may indicate a wrong proxy address, port, or network route.

## Persisting across recreations

If you use `otter assemble` with a manifest, you can embed the
proxy configuration so every container gets it automatically:

```toml
[[container]]
name  = "deb"
image = "debian"

additional.flags = [
  "--env http_proxy=http://proxy.example.com:3128",
  "--env https_proxy=http://proxy.example.com:3128",
]

hooks.pre-init = [
  "echo 'Acquire::http::Proxy \"http://proxy.example.com:3128\";' > /etc/apt/apt.conf.d/proxy.conf",
  "echo 'Acquire::https::Proxy \"http://proxy.example.com:3128\";' >> /etc/apt/apt.conf.d/proxy.conf",
]
```

This way every `otter assemble create` sets up the proxy without
needing to remember the flags each time.

Do not commit proxy passwords in a manifest, hook, or Containerfile.
Values passed through these flags are saved in the container's
configuration; use your organization's approved secret-handling
process for authenticated proxies.
