`otter exports` — manage the host-side export index.

## Synopsis

```text
otter exports list
otter exports rebuild [--scan-path <path>]...
otter exports prune   [--scan-path <path>]... [--root]
otter exports delete  <path>
```

`exp` is an alias for `exports`.

## Description

Every app or binary exported by `otter export` (run inside a
container) is recorded in a host-side **export index** under:

```text
~/.local/share/otter/exports/index/<manager>/<rootful|rootless>/<container>/
```

Each **export record** is a JSON file named after a hash of the
exported host path. The index is authoritative for ownership: it
records the container, container manager, rootful/rootless mode, the
in-container source, the host destination, and — for apps — the
exported icon. The same identity is also written into the exported file
itself, so the index can be rebuilt if it is lost.

Writes are staged (temp file, atomic replace, record last) and every
mutating operation holds a global lock at
`~/.local/share/otter/exports/.lock`. The index lives next to the
exports on the host; no symlink to it is created inside containers.

Only the owning `(container, manager, rootful/rootless)` tuple can
manage an export. All four subcommands act on the target user's files
only; running through sudo uses the invoking user's home, not root's.

## Subcommands

### `list`

Prints every recorded export across all containers, managers, and
modes. The table includes the export name, type (`app` or `binary`),
container, manager, root mode, and host path. `list` is read-only and
does not require a container runtime.

### `rebuild`

Scans otter-managed export files on disk and reconstructs or refreshes
the index from their ownership markers:

- `~/.local/bin` (binaries)
- `~/.local/share/applications` (apps)
- every additional `--scan-path`, which may be a file or a directory

`rebuild` is additive and metadata-refreshing only. It never deletes an
export file. If the ownership metadata inside a file changed, its
record is moved to the new owner's directory. Files without valid
otter ownership markers are skipped, including old exports that only
carry a legacy `# name:` marker — those stay unmanaged.

### `prune`

Removes destructive leftovers, globally:

- stale records whose exported file no longer exists, or whose file no
  longer carries matching ownership metadata
- orphaned otter-managed files that have no record
- icons under `~/.local/share/otter/icons/apps` that no record
  references
- leftover `.otter.tmp.*` and `.otter.bak.*` files in the managed
  directories and the index
- empty index directories

`prune` accepts the same `--scan-path` option as `rebuild`; extra paths
are scanned for orphaned otter-managed files. It never touches files
without valid new-style ownership markers, so legacy exports and
non-otter files are safe. Rootful records are left alone unless
`--root` is passed, because they may not be readable from a rootless
session.

### `delete <path>`

Deletes exactly one export by its absolute host path, along with its
record and — for apps — its managed icon. The path must be inside the
target user's home and the file must carry valid otter ownership
markers. This is the command used by the Remove action on exported
desktop launchers.

## Options

| Flag          | Applies to      | Description                                      |
| ------------- | --------------- | ------------------------------------------------ |
| `--scan-path` | `rebuild`, `prune` | Additional file or directory to scan (repeatable) |
| `--root`      | `prune`         | Include rootful records and files                 |

## Examples

```sh
otter exports list
```

Shows every export recorded for your user.

```sh
otter exports rebuild
```

Reconstructs the index from the default export directories.

```sh
otter exports rebuild --scan-path /srv/exports
```

Also indexes otter exports found under `/srv/exports`.

```sh
otter exports prune
```

Removes stale records, orphaned export files, unreferenced icons, and
temp/backup artifacts for rootless owners.

```sh
otter exports prune --root
```

The same, including rootful owners.

```sh
otter exports delete /home/ferret/.local/bin/htop-my-box
```

Removes that one binary export and its record.

## Notes

- The index is rebuildable but authoritative while present. Dropping it
  and running `otter exports rebuild` is safe; deleting export files by
  hand is not, because `prune` will only clean the resulting records
  when it can verify they are stale.
- `list` shows rootful entries if they are present in the index. Use
  `prune --root` to clean them.
- `otter remove` performs owner-scoped export cleanup itself. Use
  `otter remove --prune` to also remove stale records, backups, and
  temp files for the named container(s).
- The manager directory names are `podman`, `docker`, and `nerdctl`; the
  mode directory is `rootful` or `rootless`.
