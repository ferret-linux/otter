`otter export` — export an app or binary from a container to the host.

## Where this runs

Unlike most commands in this reference, `export` is not run on your
host — it's run **inside** an otter container, using a separate,
container-side `otter` wrapper that otter provisions automatically.
That in-container `otter` is a different program from the host CLI: it
lives at `/usr/bin/otter` inside the container (read-only, provisioned
by `otter create`), and understands a handful of subcommands —
`export`, `host-exec`, `doctor`, `redirect`, and `service` — which it
dispatches to the real scripts otter mounts at
`/usr/lib/otter/scripts/`. The naming is deliberate —
`otter export ...`/`otter host-exec ...` inside a container mirrors the
same `otter <verb>` convention you use on the host.

In other words: `otter enter my-box`, then run `otter export ...` from
the shell you land in. To inspect or clean the host-side result, use
`otter exports` on the host.

## Synopsis

```text
otter export <--app|--bin> [options]
```

## Description

Makes something inside the container usable directly from the host,
without needing to `otter enter` first:

- **`--app`** exports exactly one GUI application launcher. otter finds
  the app's `.desktop` file inside the container, rewrites its `Exec=`
  line to route through `otter enter ... --no-tty --`, copies exactly
  one icon, and writes the pair to
  `~/.local/share/applications` and
  `~/.local/share/otter/icons/apps` on the host. A Remove action is
  added so the export can be deleted from the desktop launcher itself.
- **`--bin`** exports a single binary as a small wrapper script written
  to the host (`~/.local/bin` by default), so typing its name on the
  host runs it inside the container transparently.

Every export is owned by the exact tuple
`(container, manager, rootful/rootless)` that created it. The manager
comes from the container's `container` environment variable, persisted
by `otter-init` at `/usr/lib/otter/container.manager`. Only the owning
tuple may create, overwrite, refresh, or delete an export. A different
container, a different runtime, or the other root mode can never claim
an export that does not belong to it.

Ownership is recorded in two places: markers inside the exported file
itself, and an authoritative export index under
`~/.local/share/otter/exports/index/`. The index is written last, after
the export file and its icon are in place, and is protected by a global
lock for the whole operation. If the index is lost, `otter exports
rebuild` can reconstruct it from the markers.

`otter remove` automatically cleans up exports owned by the container
being removed. `otter exports prune` cleans the whole index.

## Options Explained

### `--app`, `-a`

Name of the application to export — matched against the `Exec=`/`Name=`
fields of `.desktop` files found inside the container. You can also
give the path to a `.desktop` file directly, which is useful if
name-matching fails to find it (desktop files inside a container are
usually under `/usr/share/applications`).

When more than one desktop file matches, otter lists the candidates and
asks which one to export. Ranked exact `Name=` matches first, then
exact `Exec=` matches, then substring matches; regular files rank above
symlinks, and candidates with a resolvable icon rank above those
without.

### `--bin`, `-b`

Absolute path of the binary inside the container to export. The default
host name is `<binary>-<container>` for a rootless container and
`<binary>-rootful-<container>` for a rootful one.

### `--as`, `-n`

Custom name to export the binary as instead of the default. For apps,
`--as` is not used: output names are derived from the owner, the app's
desktop-file stem, and a source hash. Use `--as` to resolve a binary
name collision.

### `--sudo`, `-S`

Run the exported item with elevated privileges inside the container.
Elevation is attempted with `su-exec root` first, falling back to
`doas`, then `sudo`, depending on what's available in the container.

### `--delete`, `-dl`

Delete a previously exported application or binary owned by this
container instead of creating one. Without `--as`, exactly one matching
export must exist; multiple matches are listed and prompted for on a
terminal, or require `--as` when non-interactive.

### `--refresh`, `-R`

Regenerate an existing export in place. The source recorded for this
owner is reused rather than resolved again, so `--refresh` does not
re-prompt for app selection. The wrapper or desktop file is rewritten
and any old icons or artifacts belonging to the previous export are
removed. A missing source aborts the refresh and leaves the existing
export untouched.

### `--skip-ask`

When multiple desktop files match, select the top-ranked candidate
without prompting. This is set automatically by `otter assemble`.
`--skip-ask` is only honoured while creating an export; it never
auto-selects an entry for deletion.

### `--list-apps`, `-la`

List applications exported by this specific container, including
exports written to non-default directories.

### `--list-binaries`, `-lb`

List binaries exported by this specific container, including exports
written to non-default directories.

### `--enter-flags`, `-nf`

Extra flags to pass through to the underlying `otter enter` call that
the exported item runs when invoked. `--root`/`-r` and `--name`/`-n`
are set automatically and will trigger a warning if you also pass them
here.

### `--export-path`, `-ep`

Host directory to export a binary into. Defaults to
`~/.local/bin`, resolved relative to the real host home
(`OTTER_HOST_HOME`), never the container home. Only relevant to
`--bin`; apps always export to `~/.local/share/applications`.

### `--extra-flags`, `-ef`

Extra flags to append to the exported command itself (not to `otter
enter`) — inserted right before any arguments the app/binary is called
with.

### `--export-label`, `-el`

Text appended to the exported app's display name, so you can tell it
apart from a native install of the same app. Defaults to
`(on <container>)` (or `(on <container>, rootful)` for a rootful
container). Pass `none` to disable the suffix entirely.

## Conflict rules

otter refuses to overwrite a destination it does not own:

- A non-otter file at the destination is never overwritten.
- A file owned by a different `(container, manager, root/rootless)`
  tuple is never overwritten.
- A file owned by the same tuple but exported from a different source
  is never overwritten.
- A legacy export that only carries an old `# name:` marker is treated
  as unmanaged; it is not silently claimed or converted.

The only way to write a binary under a different name is `--as`, and a
non-interactive `--app` export that matches more than one desktop file
requires `--skip-ask`. Same-name exports found elsewhere on `PATH` or
in the index produce warnings, but do not stop an otherwise valid
export.

## Examples

```sh
otter export --app firefox
```

Exports Firefox from the current container as exactly one desktop
entry plus one icon on the host.

```sh
otter export --app code --skip-ask
```

Exports the top-ranked match without prompting, suitable for scripts.

```sh
otter export --app firefox --refresh
```

Regenerates the existing Firefox export from the source recorded in the
index, cleaning up the old icon if it changed.

```sh
otter export --bin /usr/bin/docker --sudo
```

Exports the container's `docker` binary to `~/.local/bin` on the host,
running it with elevated privileges inside the container whenever it's
invoked.

```sh
otter export --app firefox --delete
```

Removes the previously exported Firefox entry.

```sh
otter export --bin /usr/bin/htop --as htop-custom
```

Exports `htop` under the name `htop-custom` instead of the default
`htop-<container>`.

## Notes

- Must be run inside a container — otter checks for `/run/.containerenv`,
  `/.dockerenv`, or a `container` environment variable, and refuses to
  run on the bare host.
- Must **not** be run as root inside the container (it needs to resolve
  your real user's home directory).
- `--app` and `--bin` are mutually exclusive — pass exactly one.
- The in-container manager marker is required. Containers created or
  upgraded before this marker existed need `otter upgrade <container>`
  once before export will work.
- Exported binaries carry `# otter_binary`, `# otter-container:`,
  `# otter-manager:`, `# otter-rootful:`, and `# otter-source:` markers.
  Exported desktop files carry matching `X-Otter-*` keys. These markers
  are how lists, refresh, delete, rebuild, and prune recover ownership.
- `otter remove` automatically removes the container's generated
  desktop entry and every export owned by that container. Pass
  `--prune` to also remove stale records, backups, and temp files for
  the selected container(s).
- `--export-path` defaults relative to your real host home
  (`$OTTER_HOST_HOME`), not the container's home.
