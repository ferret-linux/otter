`otter remove` — remove otter-managed container environments.

## Synopsis

```text
otter rm     [options] [container...]
otter remove [options] [container...]
```

`rm` is a full alias of `remove`; the two behave identically.

## Description

Deletes the named container(s), or every otter container with `--all`.
Alongside the container itself, `remove` cleans up anything otter
created on the host on its behalf:

- Every export owned by the container in the host export index under
  `~/.local/share/otter/exports/index/`, including binaries exported to
  `~/.local/bin` or custom paths, application launchers in
  `~/.local/share/applications`, and their icons under
  `~/.local/share/otter/icons/apps`.
- Export files that carry the container's ownership markers but were
  never recorded in the index.
- The container's own generated desktop entry (as if
  `otter generate-entry --delete` had been run for it), including the
  pre-ownership legacy filename.

Only exports owned by the exact `(container, manager,
rootful/rootless)` tuple are touched. Exports belonging to another
container, another runtime, or the other root mode are never removed.

Named containers are cleaned even when they no longer exist in the
container runtime: only their host-side exports and desktop entry are
removed. In that case `--rm-home` has no known path and is refused with
a warning.

## Options

| Flag            | Alias |
| --------------- | ----- |
| `--all`         | `-a`  |
| `--root`        | `-r`  |
| `--force`       | `-f`  |
| `--rm-home`     | `-H`  |
| `--bypass-lock` | `-B`  |
| `--prune`       |       |

## Options Explained

### `--all`, `-a`

Delete every otter container.

### `--root`, `-r`

Remove a rootful container, and clean rootful exports.

### `--force`, `-f`

Force deletion of problematic containers.

### `--rm-home`, `-H`

Also remove the container's home directory on the host.

### `--bypass-lock`, `-B`

Remove the container even if it is locked.

### `--prune`

Also remove export-index leftovers for the selected container(s):
stale records, backups, temp files, and orphaned files carrying the
selected owner's markers. Scope follows the command: named containers
are pruned individually, while `--all` prunes every container matched
by `--all` in the command's manager and root mode.

Normal removal cleans the container's exports and index records on a
successful removal, or when the container is already absent. If removal
fails or the container is locked, host-side cleanup is skipped unless
`--prune` is passed.

## Examples

```sh
otter rm my-box
```

Removes `my-box`.

```sh
otter rm --force my-box2,my-box3
```

Force-removes both `my-box2` and `my-box3` (comma-separated names).

```sh
otter remove --all --force
```

Force-removes every rootless otter container.

```sh
otter remove --all --root --force --rm-home
```

Force-removes every rootful container and deletes their home
directories on the host.

```sh
otter rm --prune my-box
```

Removes `my-box` and also prunes stale export records, backups, and
temp files for that container.

## Notes

- `--root` is preferred over `sudo otter remove`. Set
  `preferences.sudo-program` to use a different
  privilege-escalation program from `sudo`.
- **Home removal safety**: `--rm-home` is refused (with a warning, not
  a hard error) if the resolved home path is empty, equals your real
  host home directory, or is one of `/`, `/home`, `/root`, `/usr` —
  otter will never delete these regardless of the flag. For containers
  created with a custom `--home`, the *custom* host directory is what
  gets removed, not the canonical in-container path. It is also refused
  when the container is already absent, because its home is unknown.
- **Locking**: locked containers are skipped with a warning, whether
  they were named explicitly or matched via `--all`. Their host-side
  exports are only pruned when `--prune` is passed. Use `otter unlock`
  first, or pass `--bypass-lock`.
- If every requested container turns out to be locked (and none
  removed), the command exits with an error rather than a silent
  no-op.
- Legacy exports that only carry an old `# name:` marker are not
  managed by the index and are left untouched.
