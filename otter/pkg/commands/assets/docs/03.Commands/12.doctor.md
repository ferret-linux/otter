`otter doctor` — diagnose the health of the current container from
inside it.

## Where this runs

Like `otter-export` and `otter-host-exec`, this is not a host command —
it's run **inside** an otter container, via the same container-side
`otter` wrapper (`/usr/bin/otter` inside the container) that
dispatches to the real script at `/usr/lib/otter/scripts/otter-doctor`.

In other words: `otter enter my-box`, then run `otter doctor` from
the shell you land in.

## Synopsis

```text
otter doctor
```

## Description

Runs a fixed set of read-only checks against the current container
and prints one `[OK]`/`[WARN]`/`[FAIL]` line per check: container
detection, borked/ready/bootstrapped state, official/rootful status,
`host-spawn` presence and version, the `/run/host` mount bridge,
network reachability, required identity environment variables, core
otter script presence, live init-system status (when the container is
initful), custom-home ownership, container user/group settings,
lock status, and host-integration socket freshness.

`doctor` makes no changes — it only reads container state and runs
read-only status commands (e.g. `systemctl is-system-running`,
`rc-status`, `runlevel`, `sv status`, `dinitctl status boot`,
depending on the container's init system).

A handful of checks (official image, rootful/rootless, network,
lock status) are informational only and never affect the exit code,
even when they print `[WARN]`. Everything else contributes to the
exit code: 0 if every non-informational check passes, non-zero if
any of them fails.

## Examples

```sh
otter doctor
```

Runs every check and prints the results, one line each.

## Notes

- Read-only: `doctor` never modifies the container.
- A `[FAIL]` on `host-spawn`, `/run/host`, or core-scripts usually
  means the container needs to be recreated with a current version
  of otter, rather than something to fix by hand inside it.
- Init-system checks only run when the container was created with
  `--init`; on non-init containers, `doctor` reports this as
  informational rather than as a failure.
