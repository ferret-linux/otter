# Host Resource Sharing

Otter's defining trait is that containers feel like the host OS.
This page catalogs what's shared by default, how each resource is
wired up, and which flags change it.

## Filesystem

- **Home directory** — your host home is bind-mounted at the same
  path inside the container, so you see the same `~`. Changes are
  bidirectional. (`--custom-home` replaces this with a separate
  mount.)
- **Host root** — the entire host filesystem is mounted at
  `/run/host`, so the container can reach anything else on the
  host at its real path under that prefix.
- **`/tmp`** — bind-mounted directly, so Unix sockets like
  `/tmp/.X11-unix` are shared with host ownership intact.

## Display (X11 & Wayland)

- The X11 socket lives under the shared `/tmp/.X11-unix`.
- For Wayland, the socket under `$XDG_RUNTIME_DIR` is made
  available: it's mounted directly in initless containers, and
  mirrored into the container's own runtime dir in `--init`
  containers.
- `DISPLAY`, `WAYLAND_DISPLAY`, `XAUTHORITY` and friends are
  resolved at login inside the container (via `host-spawn`) during
  first-boot profile setup, so GUI apps "just launch".

## Audio

- PipeWire and PulseAudio sockets live in `$XDG_RUNTIME_DIR`;
  they come in through the same runtime-dir sharing as Wayland.
- In `--init` containers the integration unit additionally
  symlinks `pipewire-*` and `pulse/*` sockets from the host
  runtime dir and re-syncs every 60 seconds.

## Devices & GPU

- `/dev` and `/sys` are bind-mounted by default, so devices are
  visible. `--unshare-devsys` removes this (see `USB & Devices` and
  `Using KVM & Libvirt in Containers`).
- GPU userspace is chosen with `--gpu`: `mesa` (default, works
  with the container's own Mesa userspace on the shared kernel
  drivers), `nvidia` (host driver libraries bind-mounted in), or
  `nvidia-toolkit` (CDI injection). See Using GPUs Inside
  Containers.

## Terminal & locale

- `TERMINFO_DIRS` is set so the host's terminfo is available too.
- First-boot integration wires the host's themes, icons, fonts,
  locale, and timezone into the container, and keeps
  `/etc/localtime` in sync via the keepalive loop (initless) or
  init integration.

## Environment

On `enter`, otter copies most of your host environment, then:

- keeps the container's own `PATH` (host `PATH` is appended);
- normalizes the XDG `*_HOME`/`*_DIRS` variables;
- excludes host-specific variables (`HOST*`, `PWD`, `SHELL`,
  `XDG_SEAT`, `XDG_VTNR`, any `XDG_*_DIRS`, and anything starting
  with `_`), plus any value containing quotes, backticks, or `$`.
- applies explicit `--add-env` overrides last.

See `otter enter` for the exact list.

## What changes it

| Flag                | Effect on sharing                                   |
| ------------------- | --------------------------------------------------- |
| `--unshare-devsys`  | Stops sharing `/dev` and `/sys`                     |
| `--unshare-netns`   | Stops sharing network (and host file syncing)       |
| `--unshare-ipc`     | Stops sharing IPC/`/dev/shm`                        |
| `--unshare-process` | Stops sharing the PID view                          |
| `--init`            | Systemd user session; sockets mirrored, not mounted |
| `--custom-home`     | Replaces the home mount                             |
