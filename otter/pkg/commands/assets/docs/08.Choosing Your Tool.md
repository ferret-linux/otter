# Choosing Your Tool

Choose based on how much host integration and isolation your task
needs. Otter runs a Linux user space in an OCI container integrated
with the host. It is not a security boundary for untrusted code;
containers can access shared host resources according to their
configuration.

## Choose Otter when

- You want a container based on a distribution that differs from your
  host, while keeping access to host files and desktop services.
- You want to control how much container state is shared, for example
  by giving a project its own home directory.
- You need Otter's image catalog, app and binary exports, settings, or
  TOML manifests to create repeatable environments.

Start with `Getting Started`, then read `Security & Isolation` to
understand the access a container has to the host. For exact behavior
and syntax, see the relevant page under `Commands`.

## Consider another approach when

- **You need to run one desktop app with sandbox permissions.**
  Flatpak is designed to distribute and run desktop applications in a
  sandbox. Read the [Flatpak introduction](https://docs.flatpak.org/en/latest/introduction.html).
- **You want a host-integrated development environment with Toolbx.**
  Toolbx focuses on interactive development and troubleshooting
  containers. See the [Toolbx project](https://containertoolbx.org/).
- **You want Distrobox's container workflow.** Distrobox runs
  distribution images in host-integrated containers. See its
  [official documentation](https://distrobox.it/).
- **You need a separate kernel or stronger isolation boundary.** Use a
  virtual machine configured for that purpose, or a security-focused
  sandbox appropriate to your threat model.
- **You want to configure every container detail yourself.** Use a
  container manager directly, such as Podman, Docker, or nerdctl.
