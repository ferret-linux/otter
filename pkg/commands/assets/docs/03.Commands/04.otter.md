`otter` is the command-line tool for creating and managing
host-integrated Linux containers — see `Getting Started`
for an introduction.

Two distinct programs share the name `otter`: the one you install and
run on your **host**, and a small, separate one that otter provisions
automatically **inside every container** for tasks that only make
sense from in there. They're covered separately below.

## On the host

This is the `otter` you install and run yourself. Every command has a
short alias alongside its full name; both behave identically.

| Command          | Alias  | What it does                                          |
| ---------------- | ------ | ----------------------------------------------------- |
| `assemble`       | `dmf`  | Manage containers declared in a manifest file.        |
| `create`         | `mk`   | Create a native-distro-like container environment.    |
| `documentation`  | `docs` | Browse otter's documentation in a terminal viewer.    |
| `enter`          | `sh`   | Enter a container environment.                        |
| `generate-entry` | `pin`  | Generate (or delete) a desktop entry for a container. |
| `inspect`        | `info` | Show detailed info about a container.                 |
| `journal`        | `logs` | Show logs of a container.                             |
| `list`           | `ls`   | List all otter-managed containers.                    |
| `lock`           | `lk`   | Lock a container to prevent removal or upgrades.      |
| `pause`          | `zz`   | Pause a running container.                            |
| `registry`       | `reg`  | Browse and manage otter's prebuilt image registry.    |
| `remove`         | `rm`   | Remove a container environment.                       |
| `restart`        | `rbt`  | Restart a container environment.                      |
| `start`          | `up`   | Start one or more containers.                         |
| `stop`           | `dn`   | Stop one or more running containers.                  |
| `unlock`         | `ulk`  | Unlock a container to allow removal and upgrades.     |
| `upgrade`        | `syu`  | Upgrade packages inside containers.                   |

Every command above also accepts `--help`/`-h` for its own usage, and
most accept `--root`/`-r` to operate on rootful containers instead of
rootless ones — see each command's own page for its full flag set.

## Inside a container

Every container `otter create` makes also gets its own copy of
`otter`, mounted read-only at `/usr/bin/otter` **inside** the
container. This is a different, much smaller program from the host
CLI above — it only understands five subcommands, and exists purely
to keep the same `otter <verb>` naming convention available from
inside a container:

|Command    |What it does                                           |
|---------- |------------------------------------------------------ |
|`doctor`   |Diagnose the container's health.                       |
|`export`   |Export an app or binary from the container to the host.|
|`host-exec`|Run a command on the host from inside the container.   |
|`redirect` |Redirect a command inside the container to the host.   |
|`service`  |Manage a service inside the container.                 |

To use these, `otter enter` a container first, then run `otter export
...` / `otter host-exec ...` / `otter doctor` / `otter redirect ...`
/ `otter service ...` from the shell you land in — see each command's
own page (each starts with a "Where this runs" note explaining the
host-vs-container distinction in more detail).
