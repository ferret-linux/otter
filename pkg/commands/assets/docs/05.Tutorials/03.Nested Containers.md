# Nested Containers

Otter containers can host other container systems inside them — Docker,
Podman, LXC, and even Waydroid (Android via LXC). This tutorial covers
all four, using a common pattern: a rootful container with an init
system and fully isolated namespaces.

## The common pattern

Every nested-container setup shares the same creation recipe:

```sh
otter create --root --init --unshare-all \
  --image debian \
  --additional-packages "<packages>" \
  <container-name>
```

The three critical flags:

- **`--root`** — real root privileges are needed for the inner
  container runtime to function properly.
- **`--init`** — an init system (systemd) manages the inner
  container's services.
- **`--unshare-all`** — isolates `/dev`, `/sys`, IPC, network, and
  PID namespaces so the inner runtime has its own clean slate to work
  with.

After creation, enter with:

```sh
otter enter <container-name> --root
```

All commands below assume you're inside the otter container at this
point.

## Docker inside otter

### Create the container

```sh
otter create --root --init --unshare-all \
  --image debian \
  --additional-packages "systemd docker" \
  docker-box
```

### Enable and start Docker

```sh
otter enter docker-box --root
```

Inside the container:

```sh
sudo systemctl enable --now docker
```

Verify it's running:

```sh
sudo systemctl status docker
```

### Test it

```sh
sudo docker run --rm -ti alpine
```

You now have a fully functional Docker daemon running inside your otter
container. Build images, run containers, compose stacks — everything
works as expected.

## Podman inside otter

### Create the container

```sh
otter create --root --init --unshare-all \
  --image debian \
  --additional-packages "systemd podman" \
  podman-box
```

### Configure subuids

Enter the container and set up subordinate UID/GID ranges for your
user:

```sh
otter enter podman-box --root
```

Inside the container:

```sh
sudo usermod --add-subuids 10000-65536 $USER
sudo usermod --add-subgids 10000-65536 $USER
```

### Configure Podman

Create the Podman configuration to use host-compatible namespaces:

```sh
cat << EOF | sudo tee /etc/containers/containers.conf
[containers]
netns="host"
userns="host"
ipcns="host"
utsns="host"
cgroupns="host"
log_driver = "k8s-file"
[engine]
cgroup_manager = "cgroupfs"
events_logger="file"
EOF
```

### Test it

Both rootless and rootful Podman should now work:

```sh
podman run --rm -ti alpine
sudo podman run --rm -ti alpine
```

## LXC inside otter

### Create the container

```sh
otter create --root --init --unshare-all \
  --image debian \
  --additional-packages "systemd lxc" \
  lxc-box
```

### Enable LXC services and set up networking

Enter the container and enable the LXC services:

```sh
otter enter lxc-box --root
```

Inside the container:

```sh
sudo systemctl enable --now lxc-monitord.service lxc-net.service \
  lxc.service lxcfs.service
```

Set up the LXC bridge network:

```sh
sudo ip link add name lxcbr0 type bridge
sudo ip link set dev lxcbr0 up
```

Find your container's main network interface and attach it to the
bridge:

```sh
ip a
```

Note the interface name (e.g. `tap0` or `eth0`), then:

```sh
sudo ip link set tap0 master lxcbr0
sudo ip address add 10.0.2.100/24 dev lxcbr0
```

### Create and run an LXC container

```sh
sudo lxc-create -n test-nested-lxc -t download
```

Select your desired distro and architecture from the interactive
prompt. Then start and attach to it:

```sh
sudo lxc-start test-nested-lxc
sudo lxc-attach test-nested-lxc
```

You should now be inside a working LXC container, with its own init
system and network stack.

## Waydroid inside otter

Waydroid runs Android apps on Linux using an LXC container. It
requires Wayland and the `binder_linux` kernel module to be available
on the **host**. You can install the DKMS from the
[choff/anbox-modules](https://github.com/choff/anbox-modules)
repository if your kernel doesn't include it.

### Create the container

For Waydroid, you need Debian-based with specific extra packages:

```sh
otter create --root --init --unshare-all \
  --image debian \
  --additional-packages "systemd libpam-systemd curl kmod dbus-x11 iptables mutter" \
  waydroid-box
```

### Install Waydroid

Enter the container:

```sh
otter enter waydroid-box --root
```

Add the Waydroid repository and install:

```sh
curl --progress-bar --proto '=https' --tlsv1.2 -Sf \
  https://repo.waydro.id/waydroid.gpg \
  --output /usr/share/keyrings/waydroid.gpg

echo "deb [signed-by=/usr/share/keyrings/waydroid.gpg] \
  https://repo.waydro.id/ bookworm main" | \
  tee /etc/apt/sources.list.d/waydroid.list

sudo apt update
sudo apt install waydroid
```

### Initialize Waydroid

Before running `waydroid init`, you need to point its environment at
the host's D-Bus and runtime directory:

```sh
export XDG_RUNTIME_DIR="/run/host/${XDG_RUNTIME_DIR}"
export DBUS_SESSION_BUS_ADDRESS="unix:path=/run/host/$(echo "${DBUS_SESSION_BUS_ADDRESS}" | cut -d '=' -f2-)"
```

These environment variables must be set every time you use Waydroid
inside the container. Consider adding them to your shell's rc file.

Then initialize:

```sh
waydroid init
```

## Notes

- **Resource overhead**: nested containers add overhead. Consider
  allocating more memory to the outer otter container with `--memory`
  if you plan to run resource-intensive workloads inside.
- **Network**: with `--unshare-all`, the outer container gets its own
  network namespace. Inner containers will share that namespace, not
  the host's. If you need the inner containers to reach the host
  network directly, omit `--unshare-netns` (or use `--unshare-all`
  without the netns component).
- **Root required**: all nested container scenarios need `--root` on
  the outer otter container. Rootless otter containers don't have the
  privileges required by inner runtimes.
- **Locked containers**: if you lock a nested-container box with
  `otter lock`, remember to unlock it before upgrading.
