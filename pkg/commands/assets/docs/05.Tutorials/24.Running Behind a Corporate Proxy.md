# Running Behind a Corporate Proxy

If your network requires a proxy to reach the internet, containers
need proxy configuration during creation — before the package
manager runs. This tutorial covers Debian/Ubuntu (which need
explicit apt proxy config) and other distros where the proxy
environment variables are enough.

## Why apt needs special handling

Unlike `dnf` (Fedora) and `pacman` (Arch), `apt` does not
respect the standard `http_proxy`/`https_proxy` environment
variables by default. It requires its own config file under
`/etc/apt/apt.conf.d/`. Without it, `apt update` and
`apt install` inside the container will fail with connection
timeouts — even if the proxy env vars are set correctly.

## Debian / Ubuntu

Set the proxy as an environment variable on the `otter create`
command itself (the container's initialization inherits it) and use
`--pre-init-hooks` to write the apt proxy config before `apt` runs:

```sh
PROXY=http://proxy.example.com:3128

http_proxy="${PROXY}" https_proxy="${PROXY}" otter create \
  --image debian \
  --pre-init-hooks "echo 'Acquire::http::Proxy \"${PROXY}\";' > /etc/apt/apt.conf.d/proxy.conf && echo 'Acquire::https::Proxy \"${PROXY}\";' >> /etc/apt/apt.conf.d/proxy.conf" \
  deb
```

The `--pre-init-hooks` writes the apt config before any package
installation happens, which is what `apt` actually honors. The
`http_proxy`/`https_proxy` variables on the command line are
inherited by the initialization for any tool that does respect
them (like `curl`, `wget`, and `git`).

To make the proxy env vars persist into every interactive session,
add them to the container's shell profile in the same hooks:

```sh
PROXY=http://proxy.example.com:3128

http_proxy="${PROXY}" https_proxy="${PROXY}" otter create \
  --image debian \
  --pre-init-hooks "echo 'Acquire::http::Proxy \"${PROXY}\";' > /etc/apt/apt.conf.d/proxy.conf && echo 'Acquire::https::Proxy \"${PROXY}\";' >> /etc/apt/apt.conf.d/proxy.conf && echo 'export http_proxy=\"${PROXY}\" https_proxy=\"${PROXY}\"' >> /etc/profile.d/proxy.sh" \
  deb
```

## Fedora / RHEL / CentOS

`dnf` respects `http_proxy`/`https_proxy` natively — no config
file needed. Export them on the `otter create` command so the
initialization and package manager pick them up:

```sh
PROXY=http://proxy.example.com:3128

http_proxy="${PROXY}" https_proxy="${PROXY}" otter create \
  --image fedora \
  fed
```

As above, use a `--pre-init-hooks` writing to `/etc/profile.d/` to
persist the variables for interactive sessions.

## Arch / Manjaro

`pacman` honors `http_proxy`/`https_proxy` directly, so like Fedora
it needs no config file. Export the vars on the command line so the
initialization and package manager pick them up:

```sh
PROXY=http://proxy.example.com:3128

http_proxy="${PROXY}" https_proxy="${PROXY}" otter create \
  --image arch \
  arch
```

As above, use a `--pre-init-hooks` writing to `/etc/profile.d/` to
persist the variables for interactive sessions.

If your proxy requires authentication, pacman's built-in support
isn't enough — set `XferCommand` in `/etc/pacman.conf` to delegate
downloading to a tool with fuller proxy support. For example, with
`curl` installed:

```sh
PROXY=http://user:pass@proxy.example.com:3128

http_proxy="${PROXY}" https_proxy="${PROXY}" otter create \
  --image arch \
  --pre-init-hooks "echo 'XferCommand = /usr/bin/curl -o %o %u --proxy ${PROXY}' >> /etc/pacman.conf" \
  arch
```

## Verifying it works

Enter the container and test connectivity:

```sh
otter enter deb
curl -I https://example.com
```

If the request succeeds (HTTP 200), the proxy is working. If it
times out, check that the proxy address and port are correct.

## Persisting across recreations

If you use `otter assemble` with a manifest, you can embed the
proxy configuration so every container gets it automatically:

```toml
[[container]]
name  = "deb"
image = "debian"

hooks.pre-init = [
  "echo 'Acquire::http::Proxy \"http://proxy.example.com:3128\";' > /etc/apt/apt.conf.d/proxy.conf",
  "echo 'Acquire::https::Proxy \"http://proxy.example.com:3128\";' >> /etc/apt/apt.conf.d/proxy.conf",
]
```

This way every `otter assemble create` sets up the proxy without
needing to remember the flags each time.
