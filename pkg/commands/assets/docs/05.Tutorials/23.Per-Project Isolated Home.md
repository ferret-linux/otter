# Per-Project Isolated Home

This tutorial walks through creating a container with its own
isolated home directory so that dotfiles, caches, and tool state
don't leak into your host home or other containers.

## Creating a container with `--home`

```sh
otter create --image fedora --home ~/dev/fedora-dev fedora-dev
```

This bind-mounts `~/dev/fedora-dev` on the host as the container's
actual home directory. Inside the container, `$HOME` resolves to
`/home/<user>` — the same path every distro expects — but the
underlying storage is your custom host directory.

If the host path doesn't exist yet, otter creates it for you.

## Verifying isolation

Enter the container and check that `$HOME` points to the expected
path:

```sh
otter enter fedora-dev
echo $HOME          # /home/<user>
ls -la ~            # shows your custom home contents
```

Now install something that writes to `~`:

```sh
pip install --user requests
```

On the host, `~/dev/fedora-dev/.local/lib/python` will contain the
install. Your real `~/.local` is untouched. Compare with a
container created without `--home` — the same install would land
directly in your host `~/.local`.

## Using manifests for reproducible setups

If you use `otter assemble`, you can set a custom home through the
manifest's `home` field:

```toml
[[container]]
name  = "fedora-dev"
image = "fedora"
home  = "/home/<user>/dev/fedora-dev"
```

This is equivalent to `--home` on the CLI and integrates with
manifest includes — a base entry can define a `home` path and
child entries can override it.

## The `/run/host` reality

Even with `--home`, your host filesystem is still mounted at
`/run/host` inside the container. This is a hard requirement for
otter — host-exec, desktop entry generation, GPU passthrough, and
journal forwarding all depend on it. You can reach your real host
home at `/run/host/home/<user>` if you need to.

This means `--home` isolates your dotfiles and configs (which
tools access via `$HOME`), but it is not a filesystem sandbox.
If you need true filesystem isolation, see `Security & Isolation`.

## Cleaning up

When you remove a container with a custom home, otter preserves
the custom host directory by default:

```sh
otter remove fedora-dev
```

This removes the container but leaves `~/dev/fedora-dev` intact.
If you want to also delete the home directory, pass `--rm-home`:

```sh
otter remove --rm-home fedora-dev
```
