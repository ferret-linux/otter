# IDE Integration

Otter containers are designed to work seamlessly with your host's
development tools. This tutorial covers how to use Visual Studio Code
and other editors with otter containers.

## VS Code Remote-Containers

Otter ships shim scripts that make VS Code's Remote-Containers ("Dev
Containers") extension work correctly against otter containers. The
problem they solve: VS Code Server always wants to use
`$HOME/.vscode-server` on the *container's* home directory, but since
otter containers usually share the real host home directory, every
container would collide on the same VS Code server install.

### How it works

The `docker-host` or `podman-host` shims intercept `exec` calls made
against otter-managed containers (detected via the `manager=otter`
container label) and transparently redirect `.vscode-server` to a
container-specific path under `/var/tmp` via a symlink. They also
forward a filtered set of the host's environment variables and
normalize the exec user, so a `code --remote` session behaves the
same way `otter enter` would.

### Setup

1. Find the shim scripts in otter's `extras/` directory:
   `docker-host` (for Docker users) or `podman-host` (for Podman
   users).

2. Copy or symlink the relevant shim somewhere on your `PATH`:

   ```sh
   sudo ln -s /path/to/otter/extras/podman-host /usr/local/bin/podman-host
   ```

3. Point VS Code's Dev Containers extension at the shim in place of
   the raw `docker`/`podman` binary. In VS Code settings:

   ```json
   {
     "dev.containers.dockerPath": "podman-host"
   }
   ```

4. Use the `vscode-otter` launcher to open a folder inside a
   container:

   ```sh
   vscode-otter my-box ~/projects/my-app
   ```

   This opens VS Code with a `vscode-remote://attached-container+...`
   folder URI pointing at that path inside the container.

### Flatpak support

Both shims transparently fall back to Flatpak's `flatpak-spawn --host`
when run from inside a Flatpak sandbox (e.g. a Flatpak build of VS
Code), so the integration keeps working in that environment too.

## JetBrains IDEs

JetBrains IDEs (IntelliJ IDEA, PyCharm, WebStorm, etc.) support
remote development via the **Gateway** and **Remote Development**
features. Since otter containers share the host filesystem and network,
you can use JetBrains' SSH-based remote development:

1. Ensure `sshd` is running inside the container:

   ```sh
   otter enter my-box -- sudo systemctl start sshd
   ```

2. In your JetBrains IDE, go to **File > Remote Development > SSH
   Connection** and connect to `localhost`. The container shares the
   host's network namespace by default, so SSH on a container port
   (forwarded to the host) works directly.

Alternatively, since otter containers share your home directory, you
can simply open project files directly from the host filesystem —
they're visible inside the container at the same path.

## General editor integration

Any editor that supports remote editing over SSH or working with
network-mounted filesystems will work with otter containers. The key
thing to understand is that otter containers share your home directory
by default, so files you edit on the host are immediately visible
inside the container and vice versa.

For editors that don't have dedicated container support, you can use
`otter enter` to drop into a shell and run your editor inside the
container:

```sh
otter enter my-box -- vim ~/projects/my-app/main.go
```

GUI apps launched inside the container appear on your host display
automatically, thanks to the shared X11/Wayland socket.
